A practical four-step guide

Give the project a voice.
Keep the allowance capped.

Contribute a fixed allowance of AI answers or voices by donating access through an API key. You prepay the provider yourself. This project takes no money or card details and never purchases or tops up credit for you.

Voice credit helps create new spoken answers and edited introductions. Fixed introductions are reused; they do not need fresh generation for each visit. Support gives you no editorial control.

How to contribute →Choose a provider

Four steps. One finite allowance.

1

Prepay the provider

Choose ElevenLabs for voices or DeepSeek for written replies. Make a manual top-up in your own provider account. Review its checkout and complete payment yourself.

2

Create a dedicated key

Name it for this project. Use the provider’s available key restrictions, credit cap and expiry. Copy the key privately; do not put it in email, a screenshot or a public post.

3

Set the site’s limits

Choose a finite character or token allowance, maximum calls and expiry in our contribution form. Submit only a key you own, with explicit consent for public visitor use.

4

Keep your withdrawal code

Save the private code returned after submission. Use it to check or revoke access. Withdrawal stops new calls; already-started calls may finish. You can also revoke the key with its provider.

Especially useful

ElevenLabs · spoken answers

Accepted model: eleven_v3. Your site allowance is measured in characters.

In Developers → Top Up, add funds manually and leave Auto Top Up off. PAYG supports self-serve accounts, including free accounts; plan features still differ. If you have a legacy or enterprise account, check its billing controls and disable paid overages yourself. Official PAYG guide · Billing controls.

Go to Developers → API Keys. Create a separate, restricted key with a credit quota and, where available, an expiry. It needs text-to-speech access and the account/subscription read used to check available allowance. Exact permission labels vary: consult the linked docs rather than enabling every permission. Key restrictions · Allowance read.

An IP restriction must match the project server’s confirmed outbound address, not your home address. A provider key cap and the site’s lifetime donation cap are separate controls.

DeepSeek · written replies

Accepted model: deepseek-flash. Your site allowance is measured in tokens, covering input and output.

Open the official platform, sign up or sign in, then use its Top Up page to add a fixed amount manually. Create a separate API key for this project. DeepSeek’s docs confirm that API costs draw from prepaid or granted balance; an insufficient balance produces a 402 response. Balance deductions and model · Insufficient-balance behaviour.

The public docs checked here do not specify a DeepSeek automatic-recharge switch or per-key spending cap. Check the live account’s billing settings before donating; keep any recurring recharge off. Do not assume a separate key creates a separate wallet.

Your key uses your account’s shared balance. A dedicated key does not create a separate wallet; the contribution form sets the finite allowance the project may use.

The site’s allowance does not renew when a provider billing period resets. Calls reserve a conservative maximum before use. A token or character allowance is not a guaranteed cash value: provider rates, model accounting and other use of your account can affect the underlying balance.

Turn off provider-side automatic top-ups and paid overages yourself. The project cannot change those settings. A restricted key that cannot pass the provider balance check will not be used for a paid call.
